## 1. Purpose

Optimize the TalkForge knowledge base for clarity, precision, maintainability, and long-term usability.

| Optimize for | Do not |
|---|---|
| Understanding + execution | New frameworks for their own sake |
| Signal | Noise and repetition |
| One canonical name per concept | Synonym sprawl |
| Simpler after each revision | Complexity without measurable value |

**Standing rule:** Every document should become simpler, clearer, and more useful after each revision. Complexity must never increase unless it creates measurable operational value.

---

## 3. Core principles

1. **Clear · Concise · Organized · Evidence-based · Actionable**  
2. **Eliminate redundancy** — merge duplicates; one stronger principle beats many similar rules  
3. **Preserve knowledge** — merge / simplify / clarify / relocate; never lose value  
4. **No framework proliferation** — extend established docs; every framework needs purpose + measurable value  
5. **Evidence integrity** — keep Established Research / Strong Evidence / Industry Practice / Internal Evidence / Working Hypothesis / Open Question distinct  
6. **Operational completeness** — every doc answers why / when / who / how / success

## 5. Decision criteria

### New Document Decision Rule (KA-001 v2 — binding)

Before creating any new top-level document, ask:

1. Does this concept already exist?  
2. Should this be a **chapter**?  
3. Should this be an **appendix**?  
4. Should this simply be a **link**?

Create a new top-level document **only if none apply**.

### Editorial criteria

| Question | If No |
|---|---|
| Does this paragraph improve understanding or execution? | Remove or rewrite |
| Does this section duplicate another authoritative home? | Point + merge |
| Does a new framework beat extending an existing one? | Do not create |
| Is terminology canonical per VOCAB-001? | Standardize |
| Would removing this lose unique knowledge? | Relocate, don’t drop |
