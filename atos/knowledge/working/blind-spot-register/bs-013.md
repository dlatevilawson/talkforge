# BS-013 — Realtime mint bypasses readiness contract

## What could fail?

`POST /api/realtime/session` uses `requireApiUser` only. It does **not** run `evaluatePracticeRouteAccess` / Living Profile readiness. Any authenticated client can mint a cost-bearing OpenAI Realtime session without passing the practice UI gate.

Practice page gating is UI/route-level. VoiceArena also has post-gate failures (missing key, SDP/peer failure, mic silent fallback, persistence failure after connect) covered partly by BS-005.

## Unintended consequences

- Cost exposure if a client calls the mint endpoint directly.
- “Practice denied” and “session mint allowed” can disagree.
- Future readiness tightening on the page won’t protect the API.

## Trust impact

Medium for members (mostly invisible); high for ops/cost and architecture integrity.

## Autonomy impact

Low.

## Complexity impact

Low to add the same readiness check used by `/app/practice`.

## Mission alignment

Coaching entry should share one authority boundary across page and cost-bearing APIs.

## Mitigation / decision

Mitigating 2026-08-05: `POST /api/realtime/session` calls `evaluatePracticeRouteAccess` before minting. Residual: BS-005 voice/mic fragility after a legitimate mint.
